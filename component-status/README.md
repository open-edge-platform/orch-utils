# Component Status Service

## Overview

Lightweight HTTP service that provides information about installed components and features in an Edge Orchestrator deployment. Implements [Proposal 1](https://github.com/open-edge-platform/edge-manageability-framework/blob/main/design-proposals/platform-component-status-service.md) from the Component Status Service Design Proposal.

## API Endpoints

### GET /v1/orchestrator

Returns orchestrator component status as JSON.

**Response Example:**
```json
{
  "schema-version": "1.0",
  "orchestrator": {
    "version": "2026.0",
    "features": {
      "application-orchestration": {"installed": true},
      "cluster-orchestration": {"installed": true},
      "edge-infrastructure-manager": {
        "installed": true,
        "inventory": {"installed": true},
        "out-of-band-management": {"installed": true},
        "device-onboarding": {"installed": false}
      },
      "observability": {"installed": true},
      "multitenancy": {"installed": true}
    }
  }
}
```

### GET /healthz, /readyz

Health check endpoints for Kubernetes probes.

## Configuration

Service uses YAML configuration generated by installer:

```yaml
schema-version: "1.0"
orchestrator:
  version: "2026.0"
  features:
    application-orchestration:
      installed: true
    edge-infrastructure-manager:
      installed: true
      device-onboarding:
        installed: false
```

## Security Architecture

### Authentication Requirements

The service uses the **same pattern as nexus-api-gw**:

```yaml
apiVersion: traefik.io/v1alpha1
kind: IngressRoute
metadata:
  name: component-status
  namespace: orch-gateway
spec:
  entryPoints: [websecure]
  routes:
    - match: Host(`api.{{ .Values.argo.clusterDomain }}`) && PathPrefix(`/v1/orchestrator`)
      priority: 40
      middlewares:
        - name: validate-jwt
        - name: secure-headers
      services:
        - name: component-status
          namespace: orch-platform
          port: 8080
  tls:
    secretName: tls-orch
```

### Why Validate JWT?

**Threat:** Exposing feature status aids attackers:
- If `observability: disabled` → attacker knows no logging/monitoring
- If `multitenancy: disabled` → attacker targets simpler privilege escalation
- If `device-onboarding: disabled` → attacker can compromise edge devices directly

**Mitigation:** JWT validation ensures only authenticated users can query feature status.

## Building

```bash
# Local build
cd component-status
make build

# Docker build
make docker-build
```

## Running Locally

```bash
# Create config file
cat > config.yaml <<EOF
schema-version: "1.0"
orchestrator:
  version: "2026.0"
  features:
    application-orchestration:
      installed: true
EOF

# Run service
CONFIG_PATH=./config.yaml PORT=8080 go run ./cmd/component-status

# Test
curl http://localhost:8080/v1/orchestrator
```

## Deployment

### Helm Installation

```bash
helm install component-status ./charts/component-status \
  -n orch-platform --create-namespace \
  --set componentStatus.orchestrator.version="2026.0"
```

### EMF Integration

EMF custom template must include:

```yaml
traefikRoute:
  enabled: true
  namespace: orch-gateway
  matchHost: Host(`api.{{ .Values.argo.clusterDomain }}`)
  priority: 40
  middlewares:
    - validate-jwt
    - secure-headers
```

### Verification

```bash
# Check IngressRoute
kubectl get ingressroute component-status -n orch-gateway -o yaml

# Verify priority is 40
kubectl get ingressroute component-status -n orch-gateway \
  -o jsonpath='{.spec.routes[0].priority}'

# Test authentication (should return 403)
curl -k https://api.<cluster-domain>/v1/orchestrator

# With valid token (should return 200)
curl -k -H "Authorization: Bearer $TOKEN" \
  https://api.<cluster-domain>/v1/orchestrator
```
