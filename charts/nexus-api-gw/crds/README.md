# nexus-api-gw CRDs

These CustomResourceDefinitions are required by `nexus-api-gw` at startup:

- The `MultiTenancy → Config → Runtime` singletons are POSTed by
  `pkg/reconciler/reconciler.go` (`TenancyDmInit`) — without these CRDs
  registered with the kube-apiserver, the gateway fatals on boot
  (CrashLoopBackOff).
- The JWT auth, API remap, and handler paths look up `Org`, `Project`,
  `Folder`, `APIMappingConfig` etc. from the CRD-backed informer cache.

They were historically installed by a separate `tenancy-datamodel` chart
(distributed as a kubectl image). After the Nexus tenancy replacement
removed that chart, `nexus-api-gw` lost its CRDs and started crashing.

Per the design proposal `platform-nexus-replacement.md` Open Issue #2,
full removal of `nexus-api-gw` is **out of scope** for the tenancy
replacement work — it still performs the catch-all `/v*` routing and
path remapping for several services. Until that work is done, the
gateway needs these CRDs.

Helm's top-level `crds/` directory is the right home: CRDs are installed
before any other manifest in this chart and are never deleted by Helm
(safe across upgrades).

When `nexus-api-gw` is finally retired, this directory and the
`tenancy-datamodel/` source directory can both be removed in the same
PR.

## Updating these files

These CRDs are generated by the Nexus DSL in
`orch-utils/tenancy-datamodel/`. Re-generate them with the upstream
`make` targets in that directory and copy the regenerated YAML here:

```bash
cd orch-utils/tenancy-datamodel
make build
cp build/crds/*.yaml ../charts/nexus-api-gw/crds/
```
